# TechChancellor v0.2.0

TechChancellor knows what your AI can already do, what it is missing, and helps it safely discover, verify, activate and reuse capabilities.

## What Changed

- A human-facing local Control Center connects discovery, capability details, decisions, activity and system status.
- Sources, implementations and capabilities are modeled separately, with evidence for personal adoption and real use.
- Upstream monitoring and delta review keep judgments fresh without blindly updating installed tools.
- The resumable Activation Execution Engine validates supported low-risk paths with pinning, static review, rollback and functional evidence.
- Production consumers can reuse AVAILABLE capabilities and record actual material use as USED.
- New candidates discovered through a capability return to the shared canonical admission and formal Chancellor pipeline.

## Why It Matters

The product is no longer just a list of promising repositories. It can preserve why something matters, distinguish a reference from a usable capability, use a verified capability in production and evaluate what that use discovers next.

## Real Example

A pinned, reviewed read-only index from awesome-claude-skills became an available Skill Ecosystem Discovery capability. Radar used it and found context-engineering-kit. Canonical evidence and formal Chancellor review produced **REFERENCE_ONLY** because incremental value was not demonstrated. Nothing from that candidate was installed or executed.

Correctly deciding not to adopt is part of the loop. This example is not preloaded personal state.

## Safety and Current Limits

SAFE_BY_CONTAINMENT remains the rule. Automatic actions are bounded, reversible and restricted to supported low-risk adapters. Arbitrary Python, Node, CLI or MCP services are not automatically executed. A secure third-party execution sandbox is still a missing platform capability.

Runtime databases, approvals, installed versions, pointers, usage receipts, caches and author reports are not shipped as defaults. Models follow environment/local configuration or the Codex CLI default, not an author-specific identifier. Missing optional tools do not break the base dashboard.

## Install or Upgrade

See the [Quick Start](../../README.md#quick-start-windows) and [upgrade precautions](../USAGE.md#upgrade). Python 3.11+ is required; the runtime uses only its standard library. Codex CLI and scheduling are optional.

Existing users must back up runtime and local install/config files outside their checkout before pulling: earlier releases tracked some personal files, which Git can remove during an update. Restore those local files as needed, run init and capability migration, then verify before re-enabling schedules. Do not delete the SQLite database.
